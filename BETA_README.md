# Чистая копия Ватэс для бета-тестирования

Подготовлена 31 октября 2026 года из архива `tea-app-main (19).zip`.

## Что очищено

- Удалены готовые темы, базовые учебные материалы и тесты, включая встроенный набор вопросов и 30 мини-тестов в старом каталоге товаров.
- Очищены назначения, названия аттестаций, результаты тестов и старые уведомления.
- Удалены демонстрационные учётные записи и их автоматическое создание при запуске.
- Название прежней компании, её сайт и почта в футере, шапке и политиках заменены невидимым символом U+200B.

Создание тем и тестов, назначение аттестаций, дедлайны, пользователи, документы и остальные модули сохранены. Каталог ассортимента не очищался: он не относится к темам и тестам.

## Первый запуск

Нужны Node.js 20.9 или новее и npm. Команды выполняются в папке проекта.

1. Установите зависимости: `npm ci`.
2. Скопируйте `.env.example` в `.env.local`.
3. Заполните `AUTH_SECRET` случайной строкой длиной не менее 32 символов. Её можно получить командой:

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
   ```

4. Укажите собственные `BOOTSTRAP_ADMIN_LOGIN` и `BOOTSTRAP_ADMIN_PASSWORD`. Пароль должен содержать не менее 8 символов. Готового пароля в архиве нет.
5. Установите `APP_ORIGIN` равным адресу запуска, например `http://127.0.0.1:3000`.
6. Для локальной разработки выполните `npm run dev` и откройте `http://127.0.0.1:3000/login`.
7. Для проверки готовой сборки выполните `npm run build`, затем `npm run start`. На внешнем сервере используйте HTTPS и его адрес в `APP_ORIGIN`.

Первый администратор создаётся из переменных окружения только при пустом списке пользователей. После его создания переменные `BOOTSTRAP_ADMIN_LOGIN` и `BOOTSTRAP_ADMIN_PASSWORD` можно очистить. Самостоятельная регистрация постороннего пользователя не создаёт администратора: сотрудников сначала добавляет администратор.

## Как заполнить реквизиты после регистрации компании

Откройте `app/lib/companyDetails.ts` и замените три значения в `COMPANY_DETAILS`:

- `name` — полное название компании;
- `websiteUrl` — адрес сайта с `https://` без завершающего слеша;
- `supportEmail` — почта поддержки и обращений по персональным данным.

Эти значения используются одновременно в футере, шапке и политиках. Пока почта не заполнена, футер показывает невидимый символ без ссылки `mailto:`. После изменения пересоберите приложение.

## Как наполнять и проверять

- Новые темы и тесты создаются в разделе материалов.
- Аттестация открывает пустой редактор. Для отправки нужны название, вопрос и заполненные варианты ответов.
- Дедлайн можно связать с уже созданной темой, тестом или документом. Ввод одного названия не создаёт готовый тест автоматически.
- Для чистого старта используйте отдельную установку с JSON-хранилищем из этого архива. При подключении существующей базы будут отображаться её данные.
- Результаты приёмки записаны в `BETA_VERIFICATION.md`.

Архив содержит полные исходные файлы. Папки зависимостей, сборки, временные данные приёмки и рабочие секреты в поставку не входят.
